01 What we are building

A checker that types every expression in the file, not just the source columns coming in and the projection going out — and that reports a real error when a function is called wrongly, using only the information the file itself carries plus whatever the user has declared.

Today sqlr infers types at the two ends of a model. The middle is dark: a CTE column like upper(status_code) never gets a type, so nothing downstream of it can be checked. This page closes that gap.

The whole thing is four passes over one tree. Nothing here parses SQL — sqlglot does that.

step 1
parse
→
step 2
qualify
→
step 3
annotate_types
→
step 4
check

Steps 1–3 are sqlglot. Step 4 is ours. The catalog we add feeds into step 3 and is read again by step 4 — the same table, in two directions.

The single most important fact about annotate_types: it infers, it never rejects. There is no error path anywhere in it. round(varchar_col, 2) gets a type and no complaint. Type checking is a pass you write yourself over the annotated tree. sqlglot supplies the types; you supply the judgement.

02 The input

One file, two CTEs, three deliberate bugs, and a source table whose schema is only three-fifths declared.

example.sql

with enriched as (
    select
        order_id,
        date_trunc('day', order_ts)                  as order_day,
        amount_cents / 100.0                         as amount,
        upper(status_code)                           as status,
        datediff('day', order_ts, current_timestamp) as age_days,
        list_extract(split(promo_csv, ','), 1)       as first_promo
    from orders
),
flagged as (
    select
        *,
        amount > 100              as is_large,
        round(status, 2)          as bogus,        -- bug 1
        zeroifnull(amount)        as safe_amount,  -- bug 2
        list_extract(first_promo) as broken       -- bug 3
    from enriched
)
select order_id, order_day, amount, is_large
from flagged
where age_days < 30

The declared schema — deliberately incomplete

DECLARED = {"orders": {"order_id": "BIGINT",
                       "order_ts": "TIMESTAMP",
                       "amount_cents": "INT"}}

# status_code and promo_csv are read by the SQL but described nowhere.

This is what adopting sqlr on a real project looks like on day one.

Three groups of columns, and the point of the example is that all three get typed:

GroupColumnsWhere the type comes from
declared order_id, order_ts, amount_cents the user's yml, straight into sqlglot's schema
inferred status_code, promo_csv backward evidence — they are fed to upper() and split(), so they must be strings (§9)
intermediate order_day, amount, status, age_days, first_promo, is_large, bogus… computed. In no source table and in no final projection — today, invisible to sqlr

The three bugs are all in that last group. bogus is the interesting one: it is never selected by the final query, so no amount of source-schema or projection-schema inference will ever see it. It is only findable by typing the middle of the file.

03 What a parse looks like

Before any of the code makes sense you need to see the shape it walks. Two projections, dumped verbatim.

>>> e = sqlglot.parse_one(SQL, read="duckdb")
>>> # the projection: list_extract(split(promo_csv, ','), 1) as first_promo
Alias(
  this=Anonymous(
    this=list_extract,
    expressions=[
      Split(
        this=Column(
          this=Identifier(this=promo_csv, quoted=False)),
        expression=Literal(this=',', is_string=True)),
      Literal(this=1, is_string=False)]),
  alias=Identifier(this=first_promo, quoted=False))

Three things to take from that dump, because all three drive design decisions later:

  1. Anonymous vs a real class. split got its own node class, exp.Split. list_extract did not — sqlglot has no class for it, so it lands in the catch-all exp.Anonymous with the written name in this. Your catalog has to key both.
  2. Arguments are named, not positional. Split holds this and expression. Anonymous holds this (the name) and expressions (the actual args). There is no uniform node.arguments.
  3. Every node is a plain tree of Expr. node.args is the dict, node.walk() is the traversal, node.type is where a type gets written.

And the projection holding our headline bug:

>>> # round(status, 2) as bogus
Alias(
  this=Round(
    this=Column(
      this=Identifier(this=status, quoted=False)),
    decimals=Literal(this=2, is_string=False)),
  alias=Identifier(this=bogus, quoted=False))

Round names its arguments this and decimals. Note that nothing about types appears anywhere in a fresh parse. That is what step 3 adds.

Gotcha you will hit within an hour. sqlglot normalises argument order into its node shape, which is not always the order written. Look at what date_trunc('day', order_ts) becomes:

TimestampTrunc(this=order_ts, unit='day')   # unit second, though written first

A signature written as (STRING, TEMPORAL) — matching the SQL you can see — will produce a confident, wrong error on perfectly valid SQL. Catalog signatures must be written against sqlglot's node order. This cost me one false positive on the first run of this exact example.

04 qualify: making every column addressable

Type inference cannot start until every column reference says which relation it came from, and select * has been turned into a real list. That is qualify's job, and it needs a schema to do it.

Here is why it matters. traverse_scope on the unqualified tree already gives you the scope graph — this is the same machinery relations.py uses today:

>>> for s in traverse_scope(e):
...     print(name, s.sources, [c.sql() for c in s.columns])

enriched     sources={'orders': Table}                    columns=['order_id', 'order_ts', 'amount_cents',
                                                                  'status_code', 'order_ts', 'promo_csv']
flagged      sources={'enriched': Scope}                  columns=['amount', 'status', 'amount', 'first_promo']
<root>       sources={'enriched': Scope, 'flagged': Scope} columns=['order_id', 'order_day', 'amount',
                                                                  'is_large', 'age_days']

Notice flagged lists only four columns. The * has not been expanded, so the six columns flowing through it are invisible. Qualifying fixes that.

The trap: a partial schema is fatal

>>> qualify(tree, schema=MappingSchema(DECLARED), dialect="duckdb")
OptimizeError: Column 'status_code' could not be resolved. Line: 6, Col: 25

This is the first real design decision. qualify validates that every column resolves, and our schema deliberately does not describe status_code. Two ways out:

Option A — reject

validate_qualify_columns=False

Qualification proceeds, but status_code and promo_csv stay unqualified in the output — UPPER("status_code"), no table prefix. Later passes cannot tell which relation they belong to.

Don't. It silently degrades exactly the columns you most need to reason about.

Option B — take

Gap-fill the schema with UNKNOWN

Give the schema every column the SQL reads; type the undeclared ones UNKNOWN. Now the schema is complete, validation passes, and everything qualifies properly.

UNKNOWN is a first-class DType in sqlglot, not a sentinel you invented. Passes below already handle it.

# Option B. The column list comes from the tree itself, so nothing has to be known
# in advance. Note this runs *before* qualify, on the scope graph shown above.
def table_columns(tree):
    """Columns read straight off a real table, per table."""
    out = {}
    for scope in traverse_scope(tree):
        tables = {n: s for n, s in scope.sources.items() if isinstance(s, exp.Table)}
        if not tables:
            continue                  # scope reads CTEs only; nothing to declare
        for col in scope.columns:
            # an unqualified column in a single-table scope belongs to that table
            name = col.table or (next(iter(tables)) if len(tables) == 1 else None)
            if name in tables:
                out.setdefault(tables[name].name, set()).add(col.name)
    return out

def gapfilled(declared, tree):
    return {t: {c: declared.get(t, {}).get(c, "UNKNOWN") for c in sorted(cols)}
            for t, cols in table_columns(tree).items()}

Filtering to exp.Table sources is what stops CTE-internal names like amount and is_large from being invented as columns of orders.

The * is gone, replaced by six real projections. Every column now names its relation. split was rewritten to STR_SPLIT — that is sqlglot normalising to DuckDB's canonical spelling, and it is harmless.

Qualification is also where an unresolvable column becomes reportable. If a user writes orders.custmer_id, Option B's gap-fill will happily invent it — so the real check for typos belongs here, comparing the tree's column set against the declared one, before gap-filling. That is a different diagnostic from anything on this page.

A lot of this is genuinely useful and you did not write any of it:

  • amount > 100 → BOOLEAN, because GT is a Predicate.

06 Reading the UNKNOWNs

Five UNKNOWNs in that output, and they have four completely different causes. Telling them apart is the difference between a useful tool and a noisy one.

ColumnCauseWhose problem
order_day Coverage gap in sqlglot. DuckDB parses date_trunc to exp.TimestampTrunc, but the dispatch table only registers the date-unit annotator for DateTrunc/DateAdd/DateSub. Nothing is wrong with the SQL. ours — fill it
first_promo No signature. list_extract is Anonymous; sqlglot cannot know its return type. split has a class but no metadata entry either. ours — catalog it
safe_amount Function does not exist in this dialect. zeroifnull is Snowflake. Also Anonymous, and indistinguishable from the row above without a catalog to check against. the user — report it
broken Wrong arity. list_extract with one argument. the user — report it
‘order_day’ in flagged and in the final projection Propagation. One UNKNOWN upstream, and every expression that touches it is UNKNOWN too. derived — do not report twice

UNKNOWN is absorbing. _annotate_by_args returns immediately with UNKNOWN the moment any argument is UNKNOWN. There is no partial recovery. One uncatalogued function near the bottom of a file blanks out everything above it — which is why order_day is UNKNOWN in all three scopes from one missing metadata entry.

The practical consequence: measure your catalog's coverage as a number, and treat "argument was typed but result is UNKNOWN" as a coverage bug to be fixed, never as a user error to be reported.

07 The signature catalog

One table, keyed by dialect and SQL function name. It is the only new data in this design, and it gets read three different ways.

from dataclasses import dataclass

@dataclass(frozen=True)
class Sig:
    params: tuple[str, ...]   # families: NUMERIC STRING TEMPORAL BOOLEAN ARRAY ANY
    returns: str              # a type string, or "@element" / "@argN"

CATALOG: dict[str, list[Sig]] = {
    "UPPER":           [Sig(("STRING",), "VARCHAR")],
    "SPLIT":           [Sig(("STRING", "STRING"), "ARRAY<VARCHAR>")],
    "LIST_EXTRACT":    [Sig(("ARRAY", "NUMERIC"), "@element")],
    "ROUND":           [Sig(("NUMERIC", "NUMERIC"), "@arg0"), Sig(("NUMERIC",), "@arg0")],
    # NOTE: params are in sqlglot's *node* arg order, not the order written in SQL.
    # date_trunc('day', ts) parses to TimestampTrunc(this=ts, unit='day').
    "TIMESTAMP_TRUNC": [Sig(("TEMPORAL", "STRING"), "@arg0")],
}

Four decisions worth defending, since this shape is the thing you would live with:

Decision 1

Key on the SQL name, never the class name

"ROUND", not exp.Round. Class names change between sqlglot versions and do not exist at all for Anonymous functions. One lookup helper covers both cases:

def catalog_key(node):
    if isinstance(node, exp.Anonymous):
        return node.name.upper()
    if isinstance(node, exp.Func):
        return node.sql_name()
    return None
Decision 2

Families, not concrete types

round accepts any numeric. Enumerating nine numeric types per parameter would make the catalog unmaintainable and unwritable by hand. Families map straight onto sqlglot's own constants:

FAMILIES = {
  "NUMERIC":  set(exp.DataType.NUMERIC_TYPES),
  "STRING":   set(exp.DataType.TEXT_TYPES),
  "TEMPORAL": set(exp.DataType.TEMPORAL_TYPES),
  "BOOLEAN":  {exp.DType.BOOLEAN},
  "ARRAY":    {exp.DType.ARRAY},
}
Decision 3

Polymorphic returns as markers

"@arg0" means "whatever the first argument was" — round(DECIMAL) stays DECIMAL, round(DOUBLE) stays DOUBLE, with one entry. "@element" unwraps an ARRAY<T> to T. Without these, list_extract would need one row per element type.

Decision 4

Three-valued family test

The whole design hinges on this returning None, not False, for an unknown type. False means "definitely wrong, report it". None means "cannot say, stay quiet". Conflating them is how a checker gets a reputation for lying.

def in_family(dtype, family):
    if family == "ANY":
        return True
    if dtype is None or dtype.is_type(exp.DType.UNKNOWN):
        return None
    return dtype.this in FAMILIES[family]

Where the real catalog comes from. Not from typing it out. DuckDB will hand you roughly 1,200 overloads with argument and return types from select * from duckdb_functions(), and Postgres the same from pg_proc. Snowflake and BigQuery have no equivalent, which is the actual cost of this whole design and the thing to scope before committing.

Note what is not in the catalog: datediff, current_timestamp, /, >. sqlglot already types all of those correctly. The catalog is a gap-filler, not a replacement — keep it that way, or you inherit 300 entries of maintenance you did not need.

08 Forward: catalog → types

Installing the catalog is 10 lines, because sqlglot's dispatch table is a plain dict you are allowed to write to.

Recall the mechanism from annotate_types.py — when it reaches a node, it does exactly this and nothing more:

spec = self.expression_metadata.get(expr.__class__)
if spec and (annotator := spec.get("annotator")):
    annotator(self, expr)
elif spec and (returns := spec.get("returns")):
    self._set_type(expr, returns)
else:
    self._set_type(expr, exp.DType.UNKNOWN)

sqlglot 30.14.0, annotate_types.py:528. Class → dict lookup → constant type or a callable. That is the entire extension point.

So to inject the catalog, put a callable in that dict for each entry:

def pick_overload(node):
    """First overload no argument definitively contradicts."""
    args = func_args(node)
    for sig in CATALOG.get(catalog_key(node) or "", []):
        if len(sig.params) != len(args):
            continue
        if any(in_family(a.type, f) is False for a, f in zip(args, sig.params)):
            continue                      # definitely the wrong overload
        return sig, args
    return None, args


def _annotate(annotator, node):
    sig, args = pick_overload(node)
    annotator._set_type(node, _resolve_return(sig, args) if sig else exp.DType.UNKNOWN)


def install_catalog(dialect_name="duckdb"):
    """Register one annotator per catalog entry, on this dialect only."""
    d = Dialect.get_or_raise(dialect_name)
    for key in CATALOG:
        cls = exp.FUNCTION_BY_NAME.get(key)      # sqlglot's own name -> class map
        if cls is not None:
            d.EXPRESSION_METADATA[cls] = {"annotator": _annotate}
    # everything with no sqlglot class arrives as Anonymous; route it by written name
    d.EXPRESSION_METADATA[exp.Anonymous] = {"annotator": _annotate}

exp.FUNCTION_BY_NAME is sqlglot's own "ROUND" → exp.Round mapping, so the catalog never has to mention a class. Entries with no class (LIST_EXTRACT) are reached through the single Anonymous registration, which dispatches on node.name.

Argument extraction is the one fiddly bit, because of the two node shapes from §3:

def func_args(node):
    """Positional arguments of a call, in sqlglot's node arg order."""
    if isinstance(node, exp.Anonymous):
        return list(node.args.get("expressions") or [])
    out = []
    for name in node.arg_types:              # declaration order, stable
        val = node.args.get(name)
        if val is None or isinstance(val, (str, bool)):
            continue                        # flags like `big_int`, not arguments
        out.extend(val if isinstance(val, list) else [val])
    return out

Two chains resolved that could not have resolved separately:

09 Backward: catalog → source types

The same table read in reverse. If a column is fed to upper(), that column is a string — and this is the only evidence anyone has about a column nobody declared.

This direction is what makes "partially inferable" schemas work. status_code and promo_csv are described nowhere, but the SQL constrains them.

def source_columns(tree):
    """Every qualified column that reads a real table, keyed by (table, column)."""
    found = {}
    for scope in traverse_scope(tree):
        for col in scope.columns:
            source = scope.sources.get(col.table)
            if isinstance(source, exp.Table):     # a Table, not a nested Scope
                found.setdefault((source.name, col.name), col)
    return found


def backward_evidence(tree):
    real = source_columns(tree)
    by_node = {id(c): k for k, c in real.items()}
    evidence = {}
    for node in tree.walk():
        if not isinstance(node, exp.Func):
            continue
        for sig in CATALOG.get(catalog_key(node) or "", []):
            args = func_args(node)
            if len(sig.params) != len(args):
                continue
            for arg, family in zip(args, sig.params):
                key = by_node.get(id(arg))
                # only claim something about a column we know nothing about
                if key and family != "ANY" and in_family(arg.type, family) is None:
                    evidence.setdefault(key, family)
            break
    return evidence

The isinstance(source, exp.Table) test is the load-bearing line. It is what separates "this column comes from a real table, so my claim is about stored data" from "this column comes from a CTE, so its type is already computed and I must not overwrite it". Without it, backward evidence would fight forward inference.

>>> backward_evidence(pass1_tree)
{'orders.status_code': 'STRING', 'orders.promo_csv': 'STRING'}

>>> widen_schema(gapfilled(DECLARED, tree), evidence)
{
  "orders": {
    "amount_cents": "INT",         # declared
    "order_id":     "BIGINT",      # declared
    "order_ts":     "TIMESTAMP",   # declared
    "promo_csv":    "VARCHAR",     # inferred: split() wants a STRING
    "status_code":  "VARCHAR"      # inferred: upper() wants a STRING
  }
}

Then re-annotate against the widened schema. Declared and inferred types are now indistinguishable to every downstream pass — the same MappingSchema, whatever the provenance. That interchangeability is the property worth protecting: it means the checker behaves identically on a fully-documented project and an undocumented one, differing only in confidence.

Every intermediate column in the file now carries a type, except the three that are bugs. That is the state the checker wants to be handed.

Guard against oscillation. Backward evidence changes the schema, which changes inference, which could produce new backward evidence. Here it converges in one round because widen_schema only writes into UNKNOWN slots — it never overwrites a type, so the schema is monotone and a second round is a no-op. Keep that property. If you ever let evidence overwrite an existing type, cap the iterations and record what changed.

This is also where sqlr's existing weighted-evidence machinery belongs rather than my setdefault: two functions can constrain one column differently, and picking a winner by first-seen is exactly the arbitrary coin-flip the design doc argues against.

10 The checking pass

Everything so far was inference. This is the only code that has an opinion, and it is a single walk over the annotated tree.

def check(tree):
    out = []
    for node in tree.walk():
        if not isinstance(node, exp.Func):
            continue
        key  = catalog_key(node)
        sigs = CATALOG.get(key or "")

        # F001 - no signature at all. Only report for Anonymous: a function with a
        # sqlglot class exists somewhere, it is our catalog that is thin.
        if not sigs:
            if isinstance(node, exp.Anonymous):
                s, e = name_span(node)
                out.append(Finding("SQLR-F001",
                    f"unknown function {node.name!r} in dialect {DIALECT}", s, e))
            continue

        # F002 - arity. Checked before types, so a 1-arg call never also
        # reports a bogus type mismatch against a 2-arg signature.
        args = func_args(node)
        if all(len(sig.params) != len(args) for sig in sigs):
            arities = sorted({len(s.params) for s in sigs})
            s, e = name_span(node)
            out.append(Finding("SQLR-F002",
                f"{key} takes {arities} arguments, {len(args)} given", s, e))
            continue

        # F003 - right arity, no overload accepts these types. Blame the
        # specific argument, on the first same-arity overload.
        sig, _ = pick_overload(node)
        if sig is None:
            for cand in sigs:
                if len(cand.params) != len(args):
                    continue
                for i, (arg, family) in enumerate(zip(args, cand.params)):
                    if in_family(arg.type, family) is False:   # False, never None
                        s, e = span(arg)
                        out.append(Finding("SQLR-F003",
                            f"{key} argument {i+1} expects {family}, "
                            f"got {arg.type.sql(DIALECT)}", s, e))
                break
    return out

  • order_day was UNKNOWN for two whole passes and never generated a finding — in_family returned None, and None is not False.
  • promo_csv was undeclared and never generated a finding, for the same reason.
  • datediff, current_timestamp and the arithmetic are not in the catalog at all, and absence from the catalog is never an error for a class-backed function.
  • broken got exactly one finding, not two. Arity is checked first and continues, so the type check never runs against a signature the call could not match anyway.

Notice the checker never looks at the SQL text, only at node.type. Everything upstream — declared yml, backward inference, sqlglot's own tables, cross-CTE propagation — has already been flattened into one uniform annotated tree. That is the property that makes this a foundation other modules can build on rather than another special case: relationship inference, constraint extraction and fixture generation can all read node.type off the same tree without knowing where any of it came from.

11 Where the spans come from

chars 492-497 is not something the checker computed. sqlglot stashes token offsets on the nodes it positioned, and the two helpers just read them.

>>> sql = "select round(status, 2) as bogus from t"
>>> for n in parse_one(sql).find(exp.Round).walk():
...     print(type(n).__name__, n.meta.get("start"), n.meta.get("end"))
Round       7    11        # the name token: sql[7:12] == "round"
Column      None None      # composite nodes carry nothing
Identifier  13   18        # "status"
Literal     21   21        # "2"

Two different helpers, because the two kinds of finding want to point at different things:

def name_span(node):
    """Just the token sqlglot positioned on this node - for a call, its name."""
    return node.meta.get("start"), node.meta.get("end")

def span(node):
    """Hull of every positioned leaf beneath a node."""
    starts = [n.meta["start"] for n in node.walk() if n.meta.get("start") is not None]
    ends   = [n.meta["end"]   for n in node.walk() if n.meta.get("end")   is not None]
    return (min(starts) if starts else None, max(ends) if ends else None)

F001 and F002 are complaints about the call, so they use name_span and underline just zeroifnull. F003 is a complaint about one argument, so it uses the hull and underlines status.

Getting this wrong is visible in the output. An earlier run used the hull for F001 and underlined zeroifnull(amount — the closing paren is not a positioned leaf, so the hull stops short of it. That is precisely the unbalanced-hull problem source.py already documents and repairs. Reuse Positions here rather than the toy span() above; it has solved this already.

12 Limits and next steps

205 lines got a working whole-file type checker. Here is what those 205 lines honestly do not do.

GapWhat it means
No implicit coercion round('3.7', 2) is flagged. In DuckDB it is legal — the string casts. A real catalog needs each parameter to say whether it coerces, and the answer is per-dialect. Expect this to be the main source of false positives on real SQL, and to be the reason you end up wanting duckdb_functions() rather than hand-written entries.
No DECIMAL(p,s) propagation @arg0 passes the whole DataType through, so it happens to work for round. Genuine precision arithmetic (DECIMAL(10,2) * DECIMAL(5,3)) needs per-warehouse rules that neither the catalog nor sqlglot models.
No variadics Sig.params is a fixed tuple, so concat(a, b, c, ...) and coalesce cannot be expressed. Needs a repeat marker on the last parameter, plus a same-type constraint across the repeats. Notice coalesce is deliberately absent from this catalog for exactly that reason.
Nullability is not tracked sqlglot has a meta["nonnull"] flag and it does propagate through unary and binary operators, but it is dropped by every function call — upper(nonnull_col) loses it. sqlr's own nullability evidence stays sqlr's job.
Aggregates and windows unmodelled No check that an aggregate is not nested inside another, that a window function has a valid frame, or that a non-grouped column appears in group by. All real errors, none of them expressible as a function signature.
Global dialect mutation install_catalog writes into Dialect.get_or_raise("duckdb"), a process-global. Fine for a demo; in sqlr, subclass the dialect or pass expression_metadata= straight to annotate_types() so two runs with different catalogs cannot interfere.
Pinned to a young API This entire layer moved in sqlglot 30 — it was Dialect.ANNOTATORS, it is now sqlglot.typing.EXPRESSION_METADATA with the {"returns"|"annotator"} shape. Pin ~=30.14 and write a test that asserts every catalog key still resolves through exp.FUNCTION_BY_NAME and still yields a non-UNKNOWN type. A minor bump will break this silently otherwise.

What to build first

  1. Generate the catalog from duckdb_functions() instead of writing it. ~1,200 overloads, exact, free, and DuckDB is already the execution engine.
  2. Delete the hardcoded sets. FUNCTION_TYPE_MAP in schema_resolution is the forward direction of this catalog; STRING_ARGUMENT_FUNCTIONS / NUMERIC_ARGUMENT_FUNCTIONS / STRING_FIRST_ARGUMENT_FUNCTIONS in facts.py are the backward direction. One table replaces all four, and stops being keyed on sqlglot class names.
  3. Write the coverage test before the catalog grows: parse a corpus, count expressions whose arguments are typed but whose result is UNKNOWN. That number is your coverage debt, and it is the only way to keep §6's four causes of UNKNOWN distinguishable as the catalog grows.
  4. Feed evidence through sqlr's weighting rather than setdefault, so two functions constraining one column differently get arbitrated instead of racing.

Everything on this page is Python layered on sqlglot. No parser was written, no Rust, no bindings. The parser was never the hard part — the catalog is, and the catalog is a data problem that a rewrite in another language would not make any smaller.
